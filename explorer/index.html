Coaching the Coach

Can an AI coach teach itself to coach better?

An AI coach rewrites the code of a puzzle-solving AI, the player, to make it better. We let the coach rewrite itself too, then tested whether the self-improved coach trains better players.

It does not. On an exam of 120 unseen puzzles, coached players scored about the same as an uncoached one. Letting the model simply think longer beat all coaching.

The setup

The player is a short program that solves a puzzle with at most two model calls.11"Player" and "coach" are the repository's task agent and meta agent. Both use the same model. The coach looks at how the player did on 25 practice puzzles and edits the player's code. One such round is a generation. In step 1, the coach may also edit its own code, so it can get better at coaching.

We ran step 1 6 times for 12 generations each. To test a coach, we froze it (either the original coach or the self-improved one from each run22From each run we took the self-edited coach whose players improved most on practice. The rule was fixed before any exam result existed [2].) and gave it a fresh, untouched player and 8 rounds on another 25 practice puzzles. The finished player then sat the exam once: 120 puzzles it had never seen.33The 120 public ARC-AGI-2 evaluation tasks [1], with 167 test inputs. A puzzle with several test inputs gives partial credit.

For comparison, the uncoached player also sat the exam as it was, and once with the model set to think longer (reasoning effort one step higher), still with two calls and two answers per puzzle. No coach could change that setting.44A gateway no agent could edit fixed the model, its reasoning effort (high; xhigh for the think-longer run), the call cap and the budget.

The result

Players trained by the original coach scored +0.4 points above the uncoached player, and players trained by a self-improved coach −1.4 points. Both differences are smaller than the noise between runs.5595% intervals: original coach minus no coach [−1.9, +2.8] points; self-improved minus no coach [−4.0, +1.3]; self-improved minus original −1.8 [−4.2, +0.6]. All include zero. Welch t-intervals [3]; the headline was pre-registered [2]. Thinking longer added about 12 points.

Did more generations help?

Coaches rarely changed themselves. Their own code changed in only 21 of 72 generations. In a follow-up that was not pre-registered [4], 4 runs continued to generation 40, and we tested coaches picked at generations 20 and 40 too. Later picks were often the very same code: in run 1, the coach picked at generations 12, 20 and 40 was one version, made at generation 1.

Its three tests scored 26.0%, 27.8% and 36.0%. That spread is pure noise, and it is larger than any difference between generations.

What to take away

  • No coach, original or self-improved, trained a player that beat the uncoached one on this exam.
  • Letting the model think longer was worth about 12 points; no coaching came close.
  • Coaches seldom rewrote themselves, and testing one unchanged coach three times moved its score by 10 points, so small differences here are noise.
  • Up close, a coach's edit can be sensible and still help only some puzzles: in the traced round, a self-check on the second try fixed one puzzle and not another. That is one round, so it illustrates how coaching works; it is not evidence about how well it works.

Caveats

  • Noise. There were only 3 to 6 runs per group. One unchanged coach scored 26.0%, 27.8% and 36.0% in three tests, and several later picks were the same code as earlier ones.
  • The original coach needed adapting. With the repository's instruction as written, the model only asked clarifying questions. We added one sentence ("work autonomously") and loosened tool-call parsing. Both kinds of coach started from this adapted version.
  • The original coach often made no edit. It ended 11 of its first 31 rounds without one, mostly from tool-call format problems. This was left as it was, as pre-registered.
  • Some coach edits broke the player. One edit passed an argument the function did not accept, and that player scored 0. Such results count.
  • Re-runs. Harness bugs forced restarts of two original-coach test runs (one of them twice) and cost one self-improvement run a generation. An early 30-minute limit cut off 49 exam answers for the no-coach and think-longer players; all were re-run under a 2 to 3 hour limit (think longer: 39.9% before, 41.1% after). Six machine restarts lost no result.
  • An untouched final player. In one follow-up test (generation-20 coach, run 4), the untouched starting player beat the best edited finalist on practice (0.70 vs 0.66), so that exam score is the untouched player's own.
  • Transcripts are partial. They were saved only for failed practice answers (1,513 of them) and contain no hidden reasoning.

Every deviation, bug and re-run is logged in DECISIONS.md [5].

Method in full

Design, fixed before the results
  • Question. With equal compute, does a coach that evolved itself train a better player than the original coach?
  • Pre-registration. DESIGN.md, splits.json and analysis.py were committed at f577cc7 before any test result existed; the follow-up plan, DESIGN_v2.md, at 991a237 before any follow-up test.
  • Model. gpt-6-luna through the OpenAI Responses API, for player and coach. Reasoning effort high for both; the think-longer exam used xhigh.
  • Player budget. At most 2 model calls and 2 answers per test input. A test input counts as solved if either answer matches exactly.
  • Coach budget. 600k tokens per coaching round.
  • Spending cap. $150, raised to $200 before the follow-up. Prices: input $0.10, cached input $0.01, output $0.50 per million tokens.
  • Enforcement. A gateway (arcexp/gateway.py) that no agent can edit is the only route to the model. It enforces the caps and keeps a ledger.
  • Sandbox. Every test input runs as an unprivileged user with no network, in a fresh directory, without access to the answers.
  • Puzzle sets. ARC-AGI-2 commit f3283f7, seed 20261117. The exam is all 120 public evaluation tasks (167 test inputs). The two practice sets have 25 training tasks each and do not overlap.
  • Score. Share of test inputs solved within each task, averaged over the 120 tasks (task-averaged pass@2).
  • Final player of a run. The two best players are re-scored on practice, the untouched starting player included; the better one sits the exam exactly once.
  • Picking a self-improved coach. Among coaches whose code differs from the original and that have at least one scored child, take the one whose children improved most on average; ties go to the earlier generation.
  • Statistics. 95% Welch t-intervals on per-run exam scores. The headline is the first matching row of a pre-written list.
What was run, in order
  1. No coach. The starting player sat the exam 3 times: 30.1%, 27.9%, 29.7% (average 29.3%).
  2. Think longer. The starting player at xhigh effort, one exam: 41.1%.
  3. Step 1. 6 self-improvement runs of 12 generations. The coach's own code changed in 21 of 72 generations (runs 1 to 6: 1, 4, 5, 1, 7, 3). Run 4 produced no qualifying coach, so 5 self-improved coaches were tested.
  4. Step 2. Original coach, 6 test runs: 26.9%, 29.4%, 30.4%, 30.4%, 31.4%, 29.4% (average 29.7%). Self-improved coaches from runs 1, 2, 3, 5, 6: 26.0%, 27.4%, 31.0%, 27.2%, 27.9% (average 27.9%).
  5. Pre-registered analysis. Original minus no coach +0.4 [−1.9, +2.8]; self-improved minus original −1.8 [−4.2, +0.6]. Headline: "Neither improver beat two plain attempts on ARC-AGI-2."
  6. Follow-up. Runs 1 to 4 continued to 40 generations; coaches picked at generations 20 and 40 were tested under the same rules. Averages at generations 0, 12, 20, 40: 29.7%, 27.9%, 29.8%, 30.3%.
  7. Code audit. 32 changed blocks in the picked coaches: 3 specific to these puzzles, 29 general.
