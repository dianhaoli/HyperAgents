Coaching the Coach
An experiment report · ARC-AGI-2 · Nov 2026

Does a self-improving coach get better at coaching?

We let an LLM agent rewrite itself while it coached another agent at ARC-AGI-2 puzzles. Then we checked whether the rewritten coach was any better.

Modelgpt-6-luna, reasoning effort high
Exam120 evaluation tasks, 167 test inputs
StatusPre-registered test + extension
Total spend$152.23

In short

  • Neither improver beat two plain attempts on ARC-AGI-2. That is the pre-registered headline. Players built by the original coach scored 29.7% on a held-out exam. A player that simply asks the model twice scored 29.3%.
  • The coaching gain was G = +0.4 points, 95% interval [−1.9, +2.8]. Players built by self-evolved coaches scored Δ = −1.8 points against the original coach's, interval [−4.2, +0.6]. Both intervals contain zero.
  • In a follow-up that was not pre-registered, coaches taken from generation 40 built players that scored +0.6 points against generation 0, interval [−6.5, +7.8]. Several "later" coaches were the same code as earlier ones, so this is weak evidence either way.
  • Raising the model's reasoning effort to xhigh, which no coach was allowed to change, scored 41.1%. The whole study cost $152.23 in model calls.

1The question

This study has two LLM agents. The player is a short program that tries to solve one ARC-AGI-2 puzzle. It may make at most two model calls and submit two answers per test input. The coach is an agent that reads the player's practice results and edits the player's code to make it better.11"Coach" and "player" are the repository's meta agent and task agent. We use the plain names throughout. The coach can also edit itself. The idea is that a coach that rewrites its own code might become a better coach over time.

We asked a narrow version of that idea. Take a coach that has evolved itself, freeze it, and give it the same budget as the original coach. Does it build a better player? An extension then asked whether coaches taken from later generations do better than coaches from earlier ones.

A "better player" has one meaning here: a higher score on a held-out exam that no coach ever saw. The exam is all 120 public ARC-AGI-2 evaluation tasks [1]. Before any pay-off result existed, we committed the design, the data splits and the analysis script [2]. That record fixed two comparisons and their 95% intervals. G asks whether players built by the original coach beat a plain baseline. Δ asks whether players built by an evolved coach beat players built by the original one.

The left loop is a source run. We ran the repository's own evolution loop for 12 generations, six times, on a 25-task practice set (runs source_s1–source_s6). In each generation the coach could edit the player, its own code, or both, starting from any earlier node in the tree. Every coach started from the same original coach, I0. We had to adapt I0 slightly before it would edit code at all.22With the repository's verbatim instruction, the model only asked clarifying questions and never edited code. One sentence was added ("work autonomously") and tool-call parsing was loosened. Both groups started from this adapted coach. DECISIONS 14, 15.

From each source run we picked one evolved coach, Ig. The rule was fixed in advance. Among coaches whose code differs from I0 and that produced at least one scored child, take the one whose children improved most. Five of the six runs had one. In source_s4, the only coach edit never produced a scored child.

The right loop is a pay-off run. A frozen coach, either I0 or an Ig, gets the plain starting player A0 and eight rounds on a second, disjoint 25-task practice set.33Each practice set has 19 tasks the starting player solves sometimes but not always, 3 it always solves and 3 it never solves. Too few intermediate tasks qualified to fill both sets with them. Its code is locked, so it can only improve the player. We ran six pay-off runs with I0 and five with an Ig. At the end, the two best players are re-scored on the practice set, and the one with the higher combined score takes the exam once. The unedited A0 is eligible to be that player.44This happened once. In the extension's source_s4 generation-20 run, A0 beat every edited player on the practice set. So that exam score is A0's own.

Underneath both loops sits a gateway. It is the only route to the model, and no agent can edit it. It fixes the model (gpt-6-luna), the reasoning effort (high), the cap of two calls and two answers per test input, and the total spending cap. Reasoning effort is an API setting for how long the model thinks before it answers.55The next level up is xhigh. We ran the plain player once at xhigh as a reference. No coach could use it. Because the gateway sets it, no coach could buy a better score by raising it.

2What an ARC puzzle is

An ARC-AGI-2 task shows a few example pairs. Each pair is an input grid of coloured cells and the output grid it should become. Somewhere in the pairs is a rule: fill the enclosed shapes, mirror the pattern, count and recolour. The player sees the examples plus a new test input and must produce the output grid exactly. That means every cell, every colour and the right size. A single wrong cell fails the answer.

The player may submit two answers per test input, and the input counts as solved if either one is exactly right. This is pass@2. Some tasks have more than one test input, and those give partial credit. The exam score is this pass@2, averaged over the 120 tasks.

3Watching answers change

Before the scores, it helps to see what the players actually produce. The figure below has two views. The first follows one practice task through a source run, generation by generation. You can see when the player's answer turns from wrong to right, and sometimes back again. The second takes one exam task and lines up every final player's two attempts against the truth.

Two things stand out. Wrong answers are often close: the rule is half-found, and a few cells or one colour are off. And outcomes are noisy. The three baseline runs are the same unedited player run three times, yet they often disagree on the same task.66Exam answer grids are kept for 17 of the 23 exam runs. 4Main result: no coach beat two plain attempts

The baseline, B0, is the unedited player A0: it asks the model for the answer twice. Run three times on the exam, it scored 30.1%, 27.9% and 29.7%, a mean of 29.3%. The six players built by the original coach averaged 29.7%. The five built by evolved coaches averaged 27.9%.

The pre-registered comparisons put numbers on that. Players built by the original coach beat B0 by G = +0.4 points, with a 95% interval of [−1.9, +2.8]. Players built by evolved coaches scored Δ = −1.8 points against the original coach's, interval [−4.2, +0.6]. Against B0 directly they scored −1.4 points, interval [−4.0, +1.3].77All intervals are Welch t-intervals [3]. This is a standard interval for the difference of two group means that does not assume the groups have equal spread. When it contains 0, the data cannot tell the difference from no effect. Every interval contains zero. We found no evidence that either coach helped, and none that evolving the coach helped or hurt.

For scale, the run-to-run standard deviation was 1.2 points for B0, 1.5 for the original-coach runs and 1.9 for the evolved-coach runs. The one lever that clearly moved the score was not coaching. A single pass of A0 at xhigh effort scored 41.1%, against 29.3% for B0. The gateway locked effort at high for every player, so no coach could reach that gain.

Coaching also did not buy its score by spending more at test time. Every final player stayed within the same two-call budget, and tokens per exam input were similar across arms. The figure's second view divides each run's score by the tokens it used.88One oddity is shown as recorded rather than corrected. For B0 rep 2, compute.json logs about 0.67 calls and 15k tokens per test input, roughly a third of the other two reps. Its score is in line with them.

5How the coaches evolved

Each source run leaves an archive tree. Every node is one saved version of the coach and player code, with its practice score. Reading the six trees side by side shows how little self-improvement actually happened. In the first 12 generations, only 21 of 72 generations (29%) changed the coach's own code. By run, from source_s1 to source_s6, that was 1, 4, 5, 1, 7 and 3 of 12.9915 of those 21 changed coaches were later chosen as the starting point for a further edit. The original coach also ended 11 of its first 31 coaching steps without any edit, mostly from tool-call format problems. This was left unchanged, as pre-registered (DECISIONS 27). Most generations spent their effort on the player.

Practice scores bounce around too. A node's score is one pass over 25 tasks, and the same player can gain or lose a few tasks on a rerun. So a "best" node is partly a lucky one. That matters for the pick rule, which favours the coach whose children improved most.

Four runs (source_s1–source_s4) were later continued to 40 generations for the extension. The small multiples share one generation axis, so you can see where source_s5 and source_s6 stop at 12.

6Do later coaches do better?

The main test compared the original coach with coaches from the first 12 generations. Perhaps self-improvement needs longer. We planned a follow-up after seeing the main result, so it is not pre-registered [4]. Runs source_s1–source_s4 were continued to 40 generations. At generations 20 and 40 we picked a coach from each, using a slightly stricter rule (at least three descendants), and tested each one exactly like a pay-off run.

The means at generations 0, 12, 20 and 40 were 29.7%, 27.9%, 29.8% and 30.3%. Generation 40 minus generation 0 is +0.6 points, interval [−6.5, +7.8]. That interval is wide and includes zero, so there is no detectable trend. Generation 12 is the five Ig runs. That is not the same set of source runs as generations 20 and 40, since it includes source_s5 and source_s6 and lacks source_s4.

There is a deeper problem. The pick rule often chose the same coach node at several generations. source_s1 picked node 1 at generations 12, 20 and 40. Re-running that one fixed coach gave players that scored 26.0%, 27.8% and 36.0%, a spread of about 10 points.1010source_s3 picked node 9 at both 20 and 40. source_s2 picked node 5 at 12 and 40, and node 9 at 20. For these runs the "paired change" is just the noise of re-running one coach (DECISIONS 37). Against that noise, a trend over generations cannot be separated out.

7Reading the transcripts

Scores say what happened, and transcripts show how. For the player, a transcript is the prompt it built and the answer the model returned. Some edited players add a second "refine" or "verify" call. For the coach, a transcript is its conversation with its tools: reading reports, listing files, running the player, writing a diff.

Two limits shape what you can see.1111The harness saved player transcripts only for practice test inputs the player failed, 1,513 of them. Solved inputs appear here as answer-only replays. No exam transcripts are shown, since the exam stayed sealed from coaches. First, the harness saved player transcripts only when the player got the input wrong. Second, a transcript holds the visible prompt and answer only. The model's hidden reasoning was never recorded, so we cannot say why it answered as it did. We can only see what it said.

8What the evolved coaches changed

If evolved coaches had learned something specific about ARC, it should show in their code. We compared all 21 picked coaches with I0: the 5 from the main test and 16 from the extension, picked at generations 6, 20, 30 and 40. Two independent judges tagged every changed piece of code (a "hunk") as either ARC-specific or general. They agreed on every hunk.

Only 3 of 32 hunks were ARC-specific. Two came from the same coach, the source_s3 Ig. It wrote its own run's scores into its prompt ("gen_1 scored 0.96, while gen_2 scored 0.84…") and warned against "hardcoded colors, shapes, or grid dimensions". The third, in a source_s4 coach picked at generation 30, pointed the coach at the evaluation log folder. That coach was stored but never tested.

The other 29 were bookkeeping and advice. Typical edits added a helper that reads past evaluation reports, lists failed tasks and flags regressions. Others added prompt text such as "be evidence-driven, compare with the parent, make one focused change, don't hard-code answers". A few were plumbing: one fixed the git diff helper to skip bytecode files, and one made the bash tool keep a persistent shell.

9Caveats and what went wrong

  • The original coach needed adapting. With the repository's verbatim instruction, the model only asked clarifying questions. One sentence ("work autonomously") was added and tool-call parsing was loosened. Both groups started from this adapted coach (DECISIONS 14, 15).
  • The original coach often made no edit. It ended 11 of its first 31 coaching steps without one, mostly from tool-call format problems. This was left unchanged, as pre-registered (DECISIONS 27).
  • Harness bugs. One bug broke the first two original-coach pay-off runs (the "pilot") before any coach ran, and both restarted with new seeds. Another discarded coach edits that created a .gitignore file. payoff_I0_2 was restarted a second time, and source_s6 kept its run but lost one of its 12 generations (DECISIONS 23, 24).
  • Some coach edits broke the player. One edit, for example, passed an argument the function did not accept, and the player scored 0. These count as real outcomes (DECISIONS 32).
  • Timeouts were re-run. An early 30-minute limit per test input cut off 49 B0 and xhigh inputs. All of them were re-run under a 2–3 hour limit, and no final score includes a timeout. xhigh was 39.9% before the re-runs and 41.1% after (DECISIONS 26, 29).
  • Infrastructure. There were 6 VM restarts and some dropped network calls. All runs resumed from logs, only in-flight work was redone, and no result was lost (DECISIONS 28, 35, 39).
  • Timing. Some steps started before earlier ones finished. Pay-off runs, for example, began before the pilot exams were scored. No result from one step chose anything in another (DECISIONS 22, 31).
  • Small samples and noise. There were 6, 5, 4 and 4 runs per group. One fixed coach (source_s1 node 1) built players that scored 26.0%, 27.8% and 36.0% across three runs.
  • An unedited final player. In source_s4's generation-20 extension run, the final player was the unedited A0. That score measures A0, not the coach.
  • Transcripts are partial. They were saved only for failed practice inputs, and they contain no hidden reasoning.

10Cost

The study cost $152.23 in model calls. Almost all of it went to players, which are cheap per call but make many calls. Coaches cost $4.19 in total. They used about 350k tokens per round in the original-coach runs and about 188k in the evolved-coach runs. The original hard stop was $150 [2], and it was raised to $200 before the extension.

Design, fixed before results · 15 items
  • Question. Given equal compute for the pay-off, does a coach that evolved itself build a better player than the original coach?
  • Pre-registration. DESIGN.md, splits.json and analysis.py were committed at f577cc7 before any pay-off result existed. The extension plan, DESIGN_v2.md, was committed at 991a237 before any extension test run.
  • Model. gpt-6-luna through the OpenAI Responses API, for both roles. Player effort was high. Coach effort was also high (the user changed it from max). There was one extra A0 pass at xhigh.
  • Player budget. At most 2 model calls and 2 answers per test input. A test input counts as solved if either answer matches the true grid exactly.
  • Coach budget. 600k tokens per coaching round.
  • Spending cap. A $150 hard stop, raised by the user to $200 before the extension.
  • Prices. Input $0.10 per million tokens, cached input $0.01 per million, output $0.50 per million. Reasoning tokens are billed as output.
  • Enforcement. The gateway (arcexp/gateway.py) is the only route to the API, and no agent can edit it. It enforces the caps, keeps a ledger by role, and refuses every call once the spending cap is reached.
  • Sandbox. Every test input runs as an unprivileged user with no network, in a fresh temporary directory, and cannot see the answers. An isolation check ran before every phase and passed every time.
  • Time limit. 3 hours per test input for every arm, never reached in the end. An early 30-minute limit was replaced, and the inputs it cut off were re-run.
  • Splits. Seed 20261117, ARC-AGI-2 commit f3283f7. The held-out exam is all 120 public evaluation tasks (167 test inputs). The screen used 100 training tasks, each given 3 single A0 calls. The two practice sets (source and pay-off) have 25 tasks each and are disjoint. They were drawn from screen tasks solved once or twice, using all 38 such tasks plus 6 always-solved and 6 never-solved fillers.
  • Scoring. The exam score is averaged over the 120 tasks. A task with several test inputs gives partial credit.
  • Final player of a run. Re-score the two best players on the pay-off set, counting any valid node including the unedited A0. Keep the one with the higher mean of loop score and re-score. Give it the exam exactly once.
  • Pick rules. Ig is the coach, among those whose code differs from I0 (compared as parsed ASTs) and that had at least one scored child, whose children improved most on average. Ties go to the earlier generation. The extension rule also requires at least 3 descendants. If no coach qualifies, it falls back to the changed coach with the most descendants.
  • Freeze mode and statistics. In pay-off and test runs the coach's code is locked. Statistics are 95% Welch t-intervals on per-run exam scores, and the headline is the first matching row of a pre-written list.
Experiments run, in order · 16 steps
  1. Smoke test. 10 tasks end to end plus one coaching round. It measured prices of $0.0028 per player call and $0.007 per coaching round, which set the "Full" design: 6 source seeds, 12 generations, 6 I0 runs and 8 rounds per pay-off run.
  2. Screen. 100 training tasks × 3 single calls, used to build the practice sets.
  3. B0. The plain player A0, two attempts, on the exam 3 times: 30.1%, 27.9% and 29.7%, mean 29.3%, SD 1.2 points. The gate (15–50%) passed.
  4. xhigh check. A0 at xhigh effort, one exam pass: 41.1%. It was 39.9% before re-running the inputs that had hit the old 30-minute limit.
  5. Pilot. The first two I0 pay-off runs, 8 rounds each, then the exam: 26.9% and 29.4%. The gate passed. A harness bug crashed the first attempt before any coach ran, and both runs restarted with new seeds (DECISIONS 23).
  6. Source runs. 6 seeds (s1–s6), with coach and player both evolving for 12 generations on the source set. Coach code changed in 21 of 72 generations. Per seed: s1 1, s2 4, s3 5, s4 1, s5 7, s6 3.
  7. Ig selection. 5 of 6 seeds had a qualifying evolved coach, created at generation 1 (s1), 5 (s2), 3 (s3), 6 (s5) and 4 (s6). Seed s4 had none, because its only coach edit had no scored child.
  8. Transplant check. Each Ig ran one trial round starting from A0, and all passed.
  9. Pay-off runs. A frozen coach got 8 rounds from A0 on the pay-off set, then one exam. The other four I0 runs scored 30.4%, 30.4%, 31.4% and 29.4%. With the pilot, the six I0 runs average 29.7%. The five Ig runs scored 26.0% (s1), 27.4% (s2), 31.0% (s3), 27.2% (s5) and 27.9% (s6), averaging 27.9%. payoff_I0_2 was restarted once more after a sanitizer bug dropped a coach edit (DECISIONS 24).
  10. Pre-registered analysis. G = +0.4 points [−1.9, +2.8]. Δ = −1.8 points [−4.2, +0.6]. Ig minus B0 = −1.4 points [−4.0, +1.3]. Headline (row 2): "Neither improver beat two plain attempts on ARC-AGI-2."
  11. Extension: evolution continued. Seeds 0–3 (source_s1–s4) were run on to 40 generations.
  12. Extension picks. Coaches were picked at generations 6, 20, 30 and 40. Those at 6 and 30 were stored and transplant-checked but not tested. Generation-20 / generation-40 picks were: seed 0 (s1) node 1 / node 1, seed 1 (s2) node 9 / node 5, seed 2 (s3) node 9 / node 9, and seed 3 (s4) node 12 / node 13.
  13. Extension test runs. 8 runs under the same rules as the pay-off runs. Generation 20 / generation 40 scored: seed 0 27.8% / 36.0%, seed 1 31.5% / 31.5%, seed 2 31.8% / 24.9%, and seed 3 27.9% / 28.9%. In seed 3's generation-20 run, the final player was the unedited A0.
  14. Extension analysis. Means at generations 0 / 12 / 20 / 40 were 29.7% / 27.9% / 29.8% / 30.3%. Generation 40 minus generation 0 = +0.6 points [−6.5, +7.8], flat within the interval. The mean paired change was +2.3 points from generation 12 to 20, and +0.6 from 20 to 40.
  15. Pick-rule comparison at generation 12. The extension rule and the committed rule agree for seeds 0–2. For seed 3, the committed rule picks no coach, and the extension rule falls back to node 6, a coach with no descendants.
  16. Diff audit of every picked coach. 32 changed hunks: 3 ARC-specific and 29 general. Two judges agreed on every hunk.
Facts worth remembering · 7 items
  • Spend. $152.23 in total: players $148.03, coaches $4.19.
  • Coach tokens per round. About 350k for I0 and 188k for Ig.
  • Player tokens per practice-task evaluation. About 27.0k under I0 and 23.5k under Ig.
  • Noise. The run-to-run SD was 1.2 points for B0, 1.5 for I0 and 1.9 for Ig. One fixed coach varied by about 10 points across re-runs.
  • The biggest lever was reasoning effort, not coaching. xhigh scored 41.1%, against 29.3% for B0, about 12 points more. No coach could change effort, because the gateway fixed it.
  • The original coach needed two small adaptations to work at all (DECISIONS 14–15): an instruction to work autonomously, and looser tool-call parsing. Even then, it ended 11 of its first 31 rounds without an edit.
  • Run conditions. There were 6 VM restarts. All runs resumed from logs, no result was lost, and no final score in any arm includes a timeout. Every deviation is recorded in DECISIONS.md (items 1–40), and every coach's code is in exp/archive_export/.
